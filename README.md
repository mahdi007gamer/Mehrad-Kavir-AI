## هویت برند و نقشه توسعه تحلیل پیج

از نوامبر ۲۰۲۶ ظاهر پنل بر اساس پالت سازمانی مهراد کویر (آبی #006FFE، فولادی #1E2B39، ذغالی #111A24، روشن #F3F5F7، خاکستری #AEB8C2) به‌روزرسانی شده و نسخه SVG مخصوص رابط از لوگوی واقعی ارسالی در app/static/mehrad-kavir-logo.svg استفاده می‌کند.

## نسخه 0.3 — Google AI Studio + منشی تلفنی هوشمند

**Google Gemini** به‌عنوان ارائه‌دهنده دوم در پنل فعال شده است: کلید API را در بخش «امنیت و اتصالات → Google AI / Gemini» ثبت کن و مدل متنی، مدل Live و مدل TTS را انتخاب کن. پس از «آزمایش Google AI» می‌توانی Gemini را به‌عنوان مغز پیش‌فرض تولید سناریو، پاسخ‌های پیش‌نویس و یادگیری از بازخورد انتخاب کنی.

صفحه جدید **منشی تلفنی AI** شامل ساخت نمونه صدای فارسی (WAV) و صندوق تماس‌های آزمایشی است. برای مکالمه تلفنی واقعی، یک ورودی رسمی Twilio Media Streams → Gemini Live در کد وجود دارد که در صورت فراهم بودن شماره فعال، HTTPS/WSS عمومی، توکن‌های معتبر، مدل Live و رضایت آگاهانه مشتری باید در محیط واقعی تست شود.

فرایند تماس: معرفی رسمی به‌عنوان دستیار AI → پرسش‌های مربوط به استعلام سازه → رضایت صریح برای ثبت اطلاعات → استخراج به‌صورت پیشنهادی → بازبینی و تأیید مدیر → انتقال به CRM. **شماره و رونوشت تماس بدون رضایت ثبت نمی‌شوند** و تماس‌ها به‌صورت پیش‌فرض خاموش هستند. هیچ ادعای قیمت قطعی یا محاسبه مهندسی از سوی AI مجاز نیست.

**محدودیت مهم:** نسخه فعلی شماره تلفن ایرانی یا SIP trunk جدیدی نمی‌خرد، خط شرکت را به سیستم وصل نمی‌کند، و Asterisk PBX را هنوز پشتیبانی عملیاتی نمی‌کند. اگر شماره مهراد کویر از اپراتور داخلی است باید قابلیت SIP/PBX آن را بررسی و آداپتور داخلی را جداگانه پیاده کرد. این نسخه همچنین تماس ورودی را پس از درخواست اپراتور به یک کارشناس زنده وصل نمی‌کند؛ فقط درخواست پیگیری را به‌صورت پیشنهادی ثبت می‌کند.

برای اتصال کامل و معماری امنیتی، راهنمای [Google Gemini & Voice AI](docs/GOOGLE_VOICE_CALL_CENTER.md) را بخوان.

**نصب نسخه جدید روی ویندوز:**
- در پوشه پروژه، git pull origin main را اجرا کن.
- سپس START-WINDOWS.bat را اجرا کن تا Python dependencies و DB migrations افزایشی اعمال شوند.
- تنظیمات و کلیدهای قبلی .env حفظ می‌شوند؛ Gemini و Twilio از فرم پنل با رمزگذاری ذخیره می‌شوند.
- برای تست نمونه صوت نیاز به Google API واقعی است. تست‌های GitHub صرفاً موارد منطقی/امنیتی را بدون تماس واقعی بررسی می‌کنند.

## نسخه 0.2 — مرکز اتصالات، واردکردن دانش، تحلیل اولیه و آپدیت امن

**بعد از دریافت جدیدترین نسخه، روی ویندوز فایل START-WINDOWS.bat را اجرا کنید.** این دستور رمز ورود و اطلاعات قبلی .env را تغییر نمی‌دهد، دیتابیس قدیمی را بدون حذف داده ارتقا می‌دهد و کلید رمزنگاری جدید VAULT_ENCRYPTION_KEY را **فقط اگر قبلاً وجود نداشته باشد** تولید می‌کند.

    cd /d "D:\Merad Kavir\Ai\Mehrad-Kavir-AI"
    git pull origin main
    START-WINDOWS.bat

سپس به http://127.0.0.1:8787 بروید و از منوی «امنیت و اتصالات» استفاده کنید.

### اتصال OpenAI از داخل پنل
1. در قسمت OpenAI، کلید شخصی API (معمولاً با sk- شروع می‌شود) را وارد کنید.
2. شناسه مدل قابل دسترس حساب API خود (مثلاً gpt-5-mini) را ثبت کنید.
3. «ذخیره» و سپس «آزمایش اتصال» را بزنید.
4. نتیجه تست واقعی از مسیر رسمی OpenAI Models API نمایش داده می‌شود. اگر مدل در دسترس نیست، مدل دیگری را انتخاب کنید.

### اتصال Instagram / Meta از داخل پنل
1. حساب @mehradkavir باید حرفه‌ای (Business یا Creator) باشد.
2. در Meta Developer App، قابلیت Instagram API with Instagram Login و مجوزهای لازم را تنظیم کنید.
3. Instagram User ID، Access Token، App Secret و Webhook Verify Token را در فرم پنل ثبت کنید. مقادیر قدیمی در پنل نمایش داده نمی‌شوند؛ برای حفظ آنها فیلد رمز را خالی بگذارید.
4. «آزمایش حساب» را بزنید. سیستم از Meta API هویت حساب متصل را می‌پرسد و فقط شناسه تطبیق‌یافته با @mehradkavir را تأیید می‌کند.
5. Webhook باید روی یک آدرس **HTTPS عمومی** به مسیر /webhooks/instagram ثبت شود. آدرس localhost در Meta قابل استفاده نیست.
6. تأیید موفق توکن به معنی تکمیل اشتراک Webhook و دریافت همه مجوزهای App Review نیست؛ این مراحل باید جداگانه آزمایش شوند.

**این نسخه اتصال حساب با OAuth خودکار ندارد.** ورود توکن رسمی از داخل پنل انجام می‌شود، اما ساخت و اخذ مجوز token همچنان در Meta Developer انجام می‌شود.

### امنیت اطلاعات اتصال
- تمام توکن‌های واردشده توسط پنل در SQLite با Fernet رمزنگاری می‌شوند؛ کلید اصلی تنها در .env خصوصی میزبان است.
- مقدار توکن بعد از ذخیره نه در API و نه در مرورگر بازگردانده نمی‌شود.
- دسترسی به ثبت، تست یا قطع اتصال فقط برای نقش owner و با CSRF معتبر ممکن است.
- اگر .env شامل کلید قدیمی API باشد، تنظیم رمزگذاری‌شده پنل آن را override می‌کند؛ قطع اتصال از پنل با یک مقدار تهی رمزگذاری‌شده، دسترسی قبلی را نیز غیرفعال می‌کند.
- **هرگز VAULT_ENCRYPTION_KEY را بعد از ذخیره توکن تغییر ندهید**؛ در غیر این صورت محتوای رمزگذاری‌شده قابل بازیابی نخواهد بود.

### دانش برند و استخراج منابع
- «دانش برند → بررسی صفحات وب‌سایت» فقط صفحات HTML مجاز روی mehradkavir.com را طبق robots.txt و سقف تعداد/حجم دریافت می‌کند.
- «واردکردن کپشن‌های اینستاگرام» تنها از API رسمی و با توکن معتبر حساب متصل دریافت می‌کند.
- مطالب تازه در صف «اسناد در انتظار بررسی» قرار می‌گیرند؛ با تأیید مدیر وارد دانش برند می‌شوند.
- هر سند مصوب قابل **ویرایش و ثبت نسخه پیشنهادی** است؛ ویرایش بدون تأیید مدیر، دانش فعلی را تغییر نمی‌دهد.
- موفقیت واردسازی به دسترسی شبکه، robots.txt، مجوزها و داده واقعی بستگی دارد؛ هیچ ادعایی درباره استخراج کامل مطالب دیده‌نشده وجود ندارد.

### Insights و CRM
- برای آمار واقعی ابتدا رسانه‌ها و بعد Insights را وارد کنید. شاخص‌های ناموجود با — نشان داده می‌شوند، نه صفر.

### قوانین پاسخ خودکار
- فقط پاسخ ثابت به سلام و احوالپرسی دقیق (بدون متن تولیدی AI) قابل تعریف است.
- به‌صورت پیش‌فرض AUTO_REPLY_ENABLED=false است. این کلید توقف در .env قرار دارد و برای فعال‌سازی، هم توکن Meta باید آزمایش شده باشد، هم مالک یک قانون را روشن کرده باشد.
- سقف محافظه‌کارانه ۲۰ ارسال در روز، حداکثر یک بار به هر مخاطب در ۳۰ روز، پنجره کمتر از ۲۳ ساعت، ثبت و عدم تلاش مجدد پس از وضعیت نامشخص اعمال می‌شود.
- پیام فنی، قیمت، شکایت، مشاوره یا هر متن غیرمنطبق با عبارت دقیق همچنان در صف تأیید انسانی قرار می‌گیرد.
- **ارسال واقعی قبل از اخذ مجوز Meta و بررسی سیاست پیام‌رسانی توصیه نمی‌شود.** فعال‌سازی فقط با رضایت و مسئولیت مدیر صورت بگیرد.

### تشخیص و اعمال آپدیت جدید با تأیید یک‌کلیکی
- بخش امنیت آخرین Commit رسمی شاخه main را با نسخه ثبت‌شده در APP_REVISION مقایسه می‌کند.
- با تأیید مالک، «درخواست آپدیت» به صف امن ارسال می‌شود.
- هنگام اجرای START-WINDOWS.bat یک عامل محلی در ویندوز فعال می‌شود که فقط مخزن رسمی و SHA تأییدشده را می‌پذیرد؛ از دیتابیس بکاپ می‌گیرد و Docker را مجدداً می‌سازد.
- اپلیکیشن تحت وب به شل ویندوز، Docker Socket یا فرمان آزاد دسترسی ندارد.
- این روش **near-real-time polling** است (نه Webhook آنی GitHub). اگر ویندوز، Docker یا عامل محلی بسته باشد، درخواست تا اجرای عامل نصب نمی‌شود.
- در لینوکس این نسخه فقط نصب/ارتقای دستی را پشتیبانی می‌کند؛ عامل آپدیت خودکار ویژه ویندوز است.

## نصب یک‌کلیکی در ویندوز

**پیش‌نیاز:** Docker Desktop فعال با Docker Compose v2 و Windows PowerShell.

1. از بالای صفحه GitHub گزینه Code سپس Download ZIP را بزنید؛ یا Git Clone کنید.
2. پوشه را باز کنید و روی فایل START-WINDOWS.bat دوبار کلیک کنید.
3. نصب‌کننده فایل خصوصی .env و اطلاعات ورود تصادفی قوی را ایجاد کرده و سرویس‌های web و worker را اجرا می‌کند.
4. آدرس http://127.0.0.1:8787 را باز کنید.
5. اطلاعات ورود در فایل خصوصی .local-credentials.txt در همان پوشه ایجاد شده است. پس از ورود، از صفحه امنیت رمز را تغییر دهید؛ تمام نشست‌های قدیمی باطل می‌شوند.
6. پس از اولین ورود، برای فعال‌سازی هوش مصنوعی OPENAI_API_KEY را در .env وارد کنید و START-WINDOWS.bat را دوباره اجرا کنید.

**اجرای مجدد، رمز و تنظیمات موجود را بازنویسی نمی‌کند.** فایل‌های خصوصی را به اشتراک نگذارید و هیچ‌وقت به GitHub Push نکنید.

## نصب یک‌کلیکی لینوکس

    git clone https://github.com/mahdi007gamer/Mehrad-Kavir-AI.git
    cd Mehrad-Kavir-AI
    bash install.sh

سپس http://127.0.0.1:8787 را در همان ماشین باز کنید. این آدرس فقط روی localhost باز است.

## نصب توسعه‌دهنده بدون Docker

    python -m venv .venv
    source .venv/bin/activate
    pip install -r requirements-dev.txt

یک نسخه خصوصی از .env.example بسازید و حداقل BOOTSTRAP_ADMIN_PASSWORD طولانی و DB_PATH مناسب را تعریف کنید. متغیرهای محیطی را به ترمینال منتقل کنید؛ برنامه به‌صورت خودکار فایل .env را بدون Docker نمی‌خواند.

    export BOOTSTRAP_ADMIN_EMAIL=admin@localhost
    export BOOTSTRAP_ADMIN_PASSWORD='a-long-unique-password-change-me'
    export DB_PATH=./data/mehrad.sqlite3
    uvicorn app.main:app --reload --port 8787

در ترمینال دوم:

    python -m app.worker

نصب ویندوز با Docker مسیر پیشنهادی است و نیاز به تنظیم دستی پکیج‌های پایتون ندارد.

## راهنمای استفاده از پنل

1. **نمای کلی:** آمار واقعی پایگاه داده و وضعیت اتصال OpenAI و Meta را بررسی کنید.
2. **صندوق پیام:** با شبیه‌ساز پیام تست ایجاد کنید؛ Worker پیش‌نویس تولید می‌کند؛ مدیر متن را ویرایش و تأیید/رد می‌کند. تأیید پیام آزمایشی *هیچ ارسال خارجی* انجام نمی‌دهد.
3. **دانش برند:** اسناد موثق را وارد کنید. سند تا تأیید مالک در پاسخ‌ها استفاده نمی‌شود.
4. **حافظه و یادگیری:** انتقاد یا اصلاح را به یک قانون دقیق تبدیل کنید. مالک آن را تأیید می‌کند؛ فقط قوانین تأییدشده به متخصص مرتبط اضافه می‌شوند.
5. **استودیو محتوا:** موضوع، مخاطب و سبک را انتخاب کنید. در صورت اتصال OpenAI، نسخه جدید سناریو ساخته و ذخیره می‌شود.
6. **امنیت و اتصالات:** وضعیت اتصال‌ها و رویدادهای مدیریتی را ببینید.

## اتصال OpenAI

در .env روی سروری که خودتان اداره می‌کنید:

    OPENAI_API_KEY=YOUR_PRIVATE_API_KEY
    OPENAI_MODEL=gpt-5-mini

سپس:

    docker compose up -d --force-recreate

اشتراک ChatGPT Plus هزینه و دسترسی API مستقل را شامل نمی‌شود؛ باید API key اختصاصی داشته باشید. مدل را مطابق مدل‌های موجود در حساب API خودتان تنظیم کنید. در صورت خطای اتصال یا عدم تطبیق مدل، سیستم به پاسخ محافظه‌کارانه بازمی‌گردد و هیچ محتوای ساختگی تولید نمی‌کند.

## اتصال رسمی Instagram

برای نسخه فعلی باید از حساب حرفه‌ای Instagram، App معتبر Meta، مجوزهای لازم، Webhook در HTTPS عمومی، اطلاعات مدیریت‌شده و یک توکن حساب رسمی استفاده کنید.

مراحل کامل و محدودیت‌ها در docs/META_SETUP.md آمده‌اند. کلیدها فقط در .env سرور تعریف می‌شوند:

    META_APP_SECRET=
    META_VERIFY_TOKEN=
    META_ACCESS_TOKEN=
    META_IG_USER_ID=
    META_GRAPH_VERSION=v25.0

Webhook در /webhooks/instagram و بررسی امضای SHA-256 فعال است. در محیط توسعه با مقادیر خالی، ارسال زنده **کاملاً بسته** است. این پروژه به رمز عبور اینستاگرام نیاز ندارد.

## استقرار روی سرور VPS

نسخه Docker به‌صورت پیش‌فرض فقط روی 127.0.0.1:8787 قابل دسترسی است. **برای اینترنت مستقیماً این Bind را به 0.0.0.0 تغییر ندهید.**

پیشنهاد:
- دامنه مدیریتی جدا مانند ai.example.com انتخاب کنید.
- Nginx یا Caddy با HTTPS، کنترل IP/VPN و نرخ محدودسازی درخواست‌ها روی همان سرور تنظیم کنید.
- APP_ENV=production و COOKIE_SECURE=true را در .env قرار دهید.
- برای داده‌های مشتری نسخه پشتیبان رمزنگاری‌شده و برنامه بازیابی داشته باشید.
- قبل از Live، دسترسی Meta و رفتار Webhook را با حساب آزمایشی بررسی کنید.

برای دیدن لاگ:

    docker compose logs --tail=100 -f web worker

برای توقف:

    docker compose down

برای به‌روزرسانی:

    git pull
    docker compose up --build -d

**برای حذف داده‌ها از docker compose down -v استفاده نکنید** مگر اینکه عمداً قصد پاک‌کردن پایگاه داده را داشته باشید.

    node --check app/static/app.js

خودکارسازی GitHub Actions فایل .github/workflows/ci.yml را اجرا می‌کند (در صورت فعال بودن Actions).

## سیاست مهندسی و امنیت

- هر کدام از نقش‌های فروش، مهندسی، پشتیبانی و محتوا دستور تخصصی مخصوص دارند؛ تصمیم‌های امنیتی در Backend اتخاذ می‌شوند و قابل واگذاری به متن مشتری نیستند.
- مدل به توکن‌های API، رمز عبور و متن کامل سوابق دیگر کاربران دسترسی ندارد.
- دانش جدید به‌صورت خودکار تأیید نمی‌شود و دستیار نمی‌تواند سیاست‌ها را از روی دایرکت تغییر دهد.
- هیچ‌کس نمی‌تواند امنیت ۱۰۰٪ و غیرقابل‌دورزدن را تضمین کند. برای استفاده سازمانی عمومی ممیزی امنیتی، تست نفوذ و طرح نگهداری داده لازم است.
- این نسخه عمداً تنها یک برند و یک حساب IG را از طریق تنظیمات پشتیبانی می‌کند؛ از اشتراک داده برندها جلوگیری می‌شود.
- اگر Meta در زمان ارسال پاسخ نامشخص برگرداند، حتماً قبل از تلاش مجدد وضعیت خارجی بررسی شود.

برای جزئیات تهدیدها docs/SECURITY.md و برای Meta docs/META_SETUP.md را بخوانید.
