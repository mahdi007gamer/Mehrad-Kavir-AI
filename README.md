## نصب یک‌کلیکی در ویندوز

**پیش‌نیاز:** Docker Desktop فعال با Docker Compose v2 و Windows PowerShell.

1. از بالای صفحه GitHub گزینه Code سپس Download ZIP را بزنید؛ یا Git Clone کنید.
2. پوشه را باز کنید و روی فایل START-WINDOWS.bat دوبار کلیک کنید.
3. نصب‌کننده فایل خصوصی .env و اطلاعات ورود تصادفی قوی را ایجاد کرده و سرویس‌های web و worker را اجرا می‌کند.
4. آدرس http://127.0.0.1:8787 را باز کنید.
5. اطلاعات ورود در فایل خصوصی .local-credentials.txt در همان پوشه ایجاد شده است.
6. پس از اولین ورود، برای فعال‌سازی هوش مصنوعی OPENAI_API_KEY را در .env وارد کنید و START-WINDOWS.bat را دوباره اجرا کنید.

**اجرای مجدد، رمز و تنظیمات موجود را بازنویسی نمی‌کند.** فایل‌های خصوصی را به اشتراک نگذارید و هیچ‌وقت به GitHub Push نکنید.

## نصب یک‌کلیکی لینوکس

    git clone https://github.com/mahdi007gamer/Mehrad-Kavir-AI.git
    cd Mehrad-Kavir-AI
    bash install.sh

سپس http://127.0.0.1:8787 را در همان ماشین باز کنید. این آدرس فقط روی localhost باز است.

## نصب توسعه‌دهنده بدون Docker

    python -m venv .venv
    source .venv/bin/activate
    pip install -r requirements-dev.txt

یک نسخه خصوصی از .env.example بسازید و حداقل BOOTSTRAP_ADMIN_PASSWORD طولانی و DB_PATH مناسب را تعریف کنید. متغیرهای محیطی را به ترمینال منتقل کنید؛ برنامه به‌صورت خودکار فایل .env را بدون Docker نمی‌خواند.

    export BOOTSTRAP_ADMIN_EMAIL=admin@localhost
    export BOOTSTRAP_ADMIN_PASSWORD='a-long-unique-password-change-me'
    export DB_PATH=./data/mehrad.sqlite3
    uvicorn app.main:app --reload --port 8787

در ترمینال دوم:

    python -m app.worker

نصب ویندوز با Docker مسیر پیشنهادی است و نیاز به تنظیم دستی پکیج‌های پایتون ندارد.

## راهنمای استفاده از پنل

1. **نمای کلی:** آمار واقعی پایگاه داده و وضعیت اتصال OpenAI و Meta را بررسی کنید.
2. **صندوق پیام:** با شبیه‌ساز پیام تست ایجاد کنید؛ Worker پیش‌نویس تولید می‌کند؛ مدیر متن را ویرایش و تأیید/رد می‌کند. تأیید پیام آزمایشی *هیچ ارسال خارجی* انجام نمی‌دهد.
3. **دانش برند:** اسناد موثق را وارد کنید. سند تا تأیید مالک در پاسخ‌ها استفاده نمی‌شود.
4. **حافظه و یادگیری:** انتقاد یا اصلاح را به یک قانون دقیق تبدیل کنید. مالک آن را تأیید می‌کند؛ فقط قوانین تأییدشده به متخصص مرتبط اضافه می‌شوند.
5. **استودیو محتوا:** موضوع، مخاطب و سبک را انتخاب کنید. در صورت اتصال OpenAI، نسخه جدید سناریو ساخته و ذخیره می‌شود.
6. **امنیت و اتصالات:** وضعیت اتصال‌ها و رویدادهای مدیریتی را ببینید.

## اتصال OpenAI

در .env روی سروری که خودتان اداره می‌کنید:

    OPENAI_API_KEY=YOUR_PRIVATE_API_KEY
    OPENAI_MODEL=gpt-5-mini

سپس:

    docker compose up -d --force-recreate

اشتراک ChatGPT Plus هزینه و دسترسی API مستقل را شامل نمی‌شود؛ باید API key اختصاصی داشته باشید. مدل را مطابق مدل‌های موجود در حساب API خودتان تنظیم کنید. در صورت خطای اتصال یا عدم تطبیق مدل، سیستم به پاسخ محافظه‌کارانه بازمی‌گردد و هیچ محتوای ساختگی تولید نمی‌کند.

## اتصال رسمی Instagram

برای نسخه فعلی باید از حساب حرفه‌ای Instagram، App معتبر Meta، مجوزهای لازم، Webhook در HTTPS عمومی، اطلاعات مدیریت‌شده و یک توکن حساب رسمی استفاده کنید.

مراحل کامل و محدودیت‌ها در docs/META_SETUP.md آمده‌اند. کلیدها فقط در .env سرور تعریف می‌شوند:

    META_APP_SECRET=
    META_VERIFY_TOKEN=
    META_ACCESS_TOKEN=
    META_IG_USER_ID=
    META_GRAPH_VERSION=v25.0

Webhook در /webhooks/instagram و بررسی امضای SHA-256 فعال است. در محیط توسعه با مقادیر خالی، ارسال زنده **کاملاً بسته** است. این پروژه به رمز عبور اینستاگرام نیاز ندارد.

## استقرار روی سرور VPS

نسخه Docker به‌صورت پیش‌فرض فقط روی 127.0.0.1:8787 قابل دسترسی است. **برای اینترنت مستقیماً این Bind را به 0.0.0.0 تغییر ندهید.**

پیشنهاد:
- دامنه مدیریتی جدا مانند ai.example.com انتخاب کنید.
- Nginx یا Caddy با HTTPS، کنترل IP/VPN و نرخ محدودسازی درخواست‌ها روی همان سرور تنظیم کنید.
- APP_ENV=production و COOKIE_SECURE=true را در .env قرار دهید.
- برای داده‌های مشتری نسخه پشتیبان رمزنگاری‌شده و برنامه بازیابی داشته باشید.
- قبل از Live، دسترسی Meta و رفتار Webhook را با حساب آزمایشی بررسی کنید.

برای دیدن لاگ:

    docker compose logs --tail=100 -f web worker

برای توقف:

    docker compose down

برای به‌روزرسانی:

    git pull
    docker compose up --build -d

**برای حذف داده‌ها از docker compose down -v استفاده نکنید** مگر اینکه عمداً قصد پاک‌کردن پایگاه داده را داشته باشید.

## سیاست مهندسی و امنیت

- هر کدام از نقش‌های فروش، مهندسی، پشتیبانی و محتوا دستور تخصصی مخصوص دارند؛ تصمیم‌های امنیتی در Backend اتخاذ می‌شوند و قابل واگذاری به متن مشتری نیستند.
- مدل به توکن‌های API، رمز عبور و متن کامل سوابق دیگر کاربران دسترسی ندارد.
- دانش جدید به‌صورت خودکار تأیید نمی‌شود و دستیار نمی‌تواند سیاست‌ها را از روی دایرکت تغییر دهد.
- هیچ‌کس نمی‌تواند امنیت ۱۰۰٪ و غیرقابل‌دورزدن را تضمین کند. برای استفاده سازمانی عمومی ممیزی امنیتی، تست نفوذ و طرح نگهداری داده لازم است.
- این نسخه عمداً تنها یک برند و یک حساب IG را از طریق تنظیمات پشتیبانی می‌کند؛ از اشتراک داده برندها جلوگیری می‌شود.
- اگر Meta در زمان ارسال پاسخ نامشخص برگرداند، حتماً قبل از تلاش مجدد وضعیت خارجی بررسی شود.

برای جزئیات تهدیدها docs/SECURITY.md و برای Meta docs/META_SETUP.md را بخوانید.
